# 7 天冲刺计划 · 收入分析 Demo

**目标**：2026-11-15 晚上，在培训课上用一套真实数据、可点击下钻的 Web 系统，讲完「这家 13 店火锅品牌 9 月收入为什么涨了 240 万」。

**判定标准**：听众看完会说「这套东西能卖」。演示环境本地可跑、断网可讲。

**技术基线**：后端 Python（FastAPI + SQLAlchemy + SQLite + pytest），前端 React 18 + TypeScript + Vite + Ant Design 5 + ECharts；AI 洞察先按规则生成。

## 演示动线（15 分钟版）

1. **开场 2 分钟**：总览页。「这家 13 店火锅品牌 9 月收入 1000 万，同比 +240 万。问题：这 240 万从哪来？能不能复制？」
2. **利润桥 3 分钟**：瀑布图。「收入贡献 +100.48 万；食材成本率上升 1.04 个百分点拖累 10.42 万；店铺房租拖累 13.76 万；其它费用拖累 37.00 万；九项合计 +48.10 万，利润 64.60 → 112.70 万。」
3. **收入拆解 3 分钟**：新店 143 万 + 同店 97.28 万。「新店是开店红利，同店 97 万才是真本事。」
4. **下钻 4 分钟**：点「大众点评」→ 同店渠道 +58 万、新店 66 万 → 漏斗（曝光 436.7 万、访问转化 14.63%、支付转化 11.44%）→ 再点「肉类」→ 销量 +17098 份、单价 +1.64 元。
5. **结论 3 分钟**：系统规则生成的结论 + 三条行动建议。「这就是：比差异、找问题、定计划、达目标。」

## 风险与预案

| 风险 | 预案 |
|---|---|
| 数据口径有争议 | 以 Excel 为准，页面上标注口径；PPT 与 Excel 不一致处写入 `backend/seed/README.md`，演示时说明「课件为示意口径」 |
| 一周做不完 | 砍到四页：总览、收入结构、渠道下钻、结论；同店与产品页保留入口 |
| 图表太花 | 统一一套主题常量；只保留瀑布、柱线、漏斗、排行 |
| 演示环境断网 | 本地起后端 + 前端静态构建，浏览器直连 localhost |
| 用户临时加需求 | 进 OpenSpec backlog，不在冲刺内插队 |
| 双远程冲突 | 每次推送前 `git pull --rebase`，只 add 自己改的文件，不 `git add -A` |
