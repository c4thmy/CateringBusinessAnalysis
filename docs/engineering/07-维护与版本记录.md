## 6. 数据管理

### 6.1 加载与重置

```bash
cd backend
.venv/bin/python -m app.seeds.load_seed                  # 空库加载；已有数据会拒绝
rm -f data/cba.db && .venv/bin/python -m app.seeds.load_seed   # 彻底重置
curl -b cookie -X POST "localhost:8000/api/seeds/load?force=true"  # 通过接口强制重载
```

### 6.2 备份与恢复

```bash
# 停后端后冷备（SQLite 单文件）
cp backend/data/cba.db backend/data/cba.db.$(date +%Y%m%d-%H%M)
# 恢复
cp backend/data/cba.db.20261108-0700 backend/data/cba.db
```

### 6.3 导入批次与覆盖语义

- 每次导入生成 `import_batch`（draft → committed / rolled_back）。
- 重新导入同一数据集+门店+期间时，旧事实行写入 `superseded_by` 指向新批次，不做物理删除；回滚时恢复旧行。
- 查询历史：`sqlite3 backend/data/cba.db "select id,dataset,filename,status,row_count from import_batch order by id desc limit 20;"`。
- 长期运行建议定期归档 `superseded_by is not null` 的历史行，或迁移到 PostgreSQL。

### 6.4 示例数据口径

`backend/seed/README.md` 记录了 8 类 CSV 的来源工作表/单元格、单位与 **16 条口径差异 + 7 条待确认**。任何数字调整先改该文件与 `docs/domain/data-caliber-notes.md`，再改代码与 `shared/fixtures`。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `uvicorn` 启动端口占用 | 8000 被旧进程占用 | `lsof -nP -iTCP:8000 -sTCP:LISTEN`，`kill <pid>` 后重启 |
| 页面 401 / 跳登录 | cookie 丢失、后端重启后密钥变化、未登录 | 重新登录；确认 `CBA_SESSION_SECRET` 未变 |
| 页面整页空白 | 前端渲染异常 | 已加 ErrorBoundary；看 console；检查 API 返回是否 4xx/5xx，或数据字段为空导致（历史问题已修） |
| 切「预算/上期」无数据 | 一期只支持同期基准 | 属预期：显示「预算未导入」空态；演示动线保持「同期」 |
| 累计口径同店显示「—」 | 门店收入只有单月数据 | 属预期：不拿单月冒充累计 |
| 导入报「不是有效的 xlsx」 | 扩展名被改/文件损坏/旧 .xls | 用 Excel 另存为 .xlsx；模板支持 .xlsx/.xlsm/.csv/.txt，≤10MB；CSV 支持 UTF-8 与 GBK |
| 导入报缺列/未知科目 | 表头与模板不一致 | 下载模板；未知科目通过 `account_mapping` 映射到标准科目 |
| 重新导入后数字没变 | 批次处于 draft 未 commit | 在数据导入页确认入库；检查 `import_batch.status` |
| `npm run build` 报 TS 找不到刚加的导出 | `node_modules/.tmp` 陈旧 tsbuildinfo | `rm -rf frontend/node_modules/.tmp` 后重跑 |
| `npm install` 提示 fsevents install scripts | npm 安全策略 | 不影响构建，可忽略；或按提示 approve |
| 前端 real 模式接口 404 | 后端未起 / 路径少 `/analysis` 前缀 | 确认 Vite 代理到 8000；接口以 `shared/api-contract.md` 为准 |
| `git push origin` 被拒 | 本机身份 c4thmy 无 cfmypian 仓库权限 | 用 cfmypian 登录/凭据后补推，或把 origin 换到 c4thmy 下备份仓库 |
| SQLite `database is locked` | 并发写/长事务 | 单进程演示一般不会；避免同时跑多个 uvicorn 指向同一库；必要时启用 WAL（见技术债） |

## 11. 安全与合规

- 部署前必须修改：`CBA_ADMIN_PASSWORD`、`CBA_SESSION_SECRET`。
- Cookie 为 httpOnly + SameSite=Lax；本地 HTTP 部署未开 `Secure`，公网部署需 HTTPS 并在代码中开启 `secure=True`。
- CORS 白名单当前仅 `127.0.0.1:5173 / localhost:5173`；换端口/域名需同步。
- 数据库文件包含经营数据，按客户要求做权限控制与备份加密；不要提交到 Git。
- 系统不向任何第三方发送数据（无大模型、无遥测）；如后续接入大模型，需先做数据脱敏与合规评估。
- v0.3.4 已修静态资源路径穿越（`_resolve_dist_file()` 校验目标在 `dist` 内）与导入预览内部键泄漏（`_preview()` 过滤 `_` 前缀）；仍无 HTTPS/WAF/访问审计，**不要直接把 8000 暴露公网**。
