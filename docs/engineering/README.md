## 5. 维护约定

1. **需求变化**：先在 `openspec/changes/<id>/` 更新 proposal/specs，再同步 01/02/04/10/11/13/14/18。
2. **接口/字段变化**：同步 `shared/api-contract.md` 与 11；破坏性变更登记到 16 的变更控制。
3. **口径变化**：先改 `docs/domain/data-caliber-notes.md` 与 `backend/seed/README.md`，再改代码与验收数字（01/05/14/06）。
4. **版本发布**：代码与文档一起提交；打新 tag 后更新 07 的版本历史与根 `README.md` 的「已有标签」。
5. **文档质量**：所有「已实现」结论必须可指向代码/测试/接口；不确定处写「待确认」，不得编造。
6. **第二期**：模块实现后补对应需求/设计/数据/接口/测试/用户章节，并在 07 与技术债清单登记。
