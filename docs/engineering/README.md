所有文档描述的是**当前已实现的一期 Demo**；二期能力只做规划，均明确标注「未实现」。

## 5. 维护约定

1. **需求变化**：先在 `openspec/changes/<id>/` 更新 proposal/specs，再同步 01/02/04/05；不要只改代码。
2. **接口/字段变化**：同步 `shared/api-contract.md` 与 04；破坏性变更必须在 01 的变更记录中登记。
3. **口径变化**：先改 `docs/domain/data-caliber-notes.md` 与 `backend/seed/README.md`，再改代码与验收数字（01/05/06）。
4. **版本发布**：代码与文档一起提交；打新 tag 后更新 07 的版本历史与 `README.md` 的「已有标签」。
5. **文档质量**：所有「已实现」结论必须可指向代码/测试/接口；不确定处写「待确认」，不得编造。
6. **第二期**：毛利/费用/顾客&竞争/总结&计划/沙盘/报告实现后，需新增对应详细设计与测试章节，并在 07 登记。
