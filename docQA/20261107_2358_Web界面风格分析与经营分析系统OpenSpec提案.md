## 问答 1：分析截图中 Web 界面的风格

**提问**

看一下图中 web 界面的风格（截图为 Profit Pilot 的 Dashboard 页面，地址 ppv2.broadmind.cn/dashboard）。

**回答**

整体是典型的 B 端 SaaS 数据看板，接近 Ant Design 的设计语言，图表是 ECharts 风格。

1. 布局：
   - 左侧深色导航：Logo、品牌切换、按分析任务分组的菜单（"找问题"下有菜单诊断、健康度排行、产品分析等），底部是数据就绪状态和用户区。
   - 白色顶栏：左边是页面标题（前面一条蓝色竖线），右边是刷新、门店下拉、日期区间、更多菜单。
   - 浅灰内容区，上面是白色卡片栅格：上排 3 列 KPI 卡片，下排 2 列图表卡片。
   - 右下角有悬浮的 AI 对话按钮。
2. 配色：主色为品牌蓝（约 #2F54EB）；红色表示负向，绿色表示健康；文字分深灰、浅灰两级，关键值用蓝色加粗。
3. 组件：
   - KPI 卡片：数值、环比变化、"问 AI 排查原因"入口，以及 P25 / P50 / P75 分位和本店值。
   - 图表卡片：右上角有"AI 洞察"按钮，卡片内有分段选择器和分位线说明。
4. 亮点：AI 入口嵌在每个指标旁边；每个指标都对标同行分位；菜单按分析任务组织。
5. 可改进的地方：
   - 门店对比用红绿两色区分门店，容易被读成好坏，色弱用户也难分辨。
   - 趋势图的 X 轴日期标签过密。
   - 浅灰文字的对比度可能达不到 WCAG AA。
6. 建议技术栈：React + Ant Design 5 + ECharts（或 Vue 3 + Element Plus / Ant Design Vue + ECharts）。

> 用户随后把这部分内容整理到了 `docs/webUI.md`。

## 问答 2：提出系统需求并生成 OpenSpec 提案

**提问**

需要系统包括：营业利润分析、收入分析、毛利分析、费用分析、顾客&竞争分析、总结&计划、数据导入模块、沙盘预演及结果方案获取。

**回答与操作**

1. 调用 `openspec-propose` skill。确认 OpenSpec 根目录存在（`openspec context`），`config.yaml` 中没有额外的 context 或 rules，没有已有的 specs 或 changes。
2. 读取业务资料（环境里没有 openpyxl，改用 Python 标准库 zipfile + XML 解析，临时脚本放在 `/tmp/cba`，用完已删除）：
   - xlsx 共 18 个工作表，提取了公式和缓存数值。重点是"第一步-2509餐饮利润桥"的原始数据：2024-09 收入 760，2025-09 收入 1000，以及各费用科目。
   - pptx 80 页，提取了每页标题和要点，章节对应 6 个分析模块，另有知识库页（第 67–79 页）。
3. 创建 change：`openspec new change "build-catering-analysis-platform"`，依次写入：
   - `proposal.md`：说明为什么要做（Excel + PPT 手工分析无法复用，也不能推演）、改动内容、10 个新能力和影响范围，以及不在本次范围的内容（真实大模型 AI、第三方 API、多租户、移动端）。
   - `specs/`（10 个能力）：
     | 能力 | 内容 |
     |---|---|
     | app-workspace | 登录、导航顺序、全局筛选（品牌/门店/期间/当月或累计/同期、预算、上期）、KPI 卡片规范、规则化洞察 |
     | data-import | 11 类数据集模板、校验、预览确认、覆盖导入、批次回滚、数据就绪状态、示例数据 |
     | factor-analysis-engine | 对比差异、连环替代法、营业利润桥、结构/单项拆分、分位数、精度规则 |
     | profit-analysis | 预算达成、利润表对比、利润桥瀑布图、综合评分、业务板块汇总 |
     | revenue-analysis | 收入结构、同店客流×客单、同店渠道异动、系列单品销量×单价、曝光转化漏斗、平台 ROI、异动汇总 |
     | gross-margin-analysis | 毛利总览、毛利率结构拆分、毛利额三因素替代、单价/成本对毛利率影响、理论成本损益、折扣率影响 |
     | expense-analysis | 费用科目对比、人效/坪效/租售比/上座次数/营销投产比、模型值对比、门店排行 |
     | customer-competition-analysis | 加权满意度、分项评分、评价关键词、会员储值、竞对监测 |
     | summary-plan | 月度总结草稿、下月目标、待办整改清单、计划导出、时段营业额预估 |
     | sandbox-simulation | 基期方案、驱动因子调整、实时推演、目标反推、多方案对比、结果方案输出、方案转计划 |
   - `design.md`：
     - 技术栈：前端 React 18 + TS + Vite + antd 5 + ECharts；后端 FastAPI + SQLAlchemy + SQLite + pandas/openpyxl。
     - 数据按长表加维度存储；导入分两阶段提交，回滚通过 `superseded_by` 标记实现。
     - 沙盘在前端用 TS 实时复算，后端再算一遍作为权威结果，两端共用 `shared/fixtures` JSON 用例。
     - 利润桥的科目分类（变动/固定）可配置；洞察和整改建议都基于规则库；认证为单管理员 JWT。
   - `tasks.md`：13 组、41 个任务，每个任务都写了验证方式。顺序为：脚手架 → 引擎 → 数据模型/认证 → 导入 → 框架组件 → 6 个分析模块 → 沙盘 → 集成验收。
4. 验收数字（根据 Excel 原始数据手算核对）：
   - 利润桥：去年利润 64.6 → 收入规模 +100.5、食材成本率 −10.4、优惠及手续费 +12.9、水电气低值 +2.2、宣传费用 +7.4、工资奖金 −12.0、宿舍房租 −1.7、店铺房租 −13.8、其它费用 −37.0 → 今年利润 112.7（万元）。
   - 毛利率 73.3% 对 74.3%，下降 1.0pp；同店 857.23、新店 143；美团大众 +124（+36.9%）。
   - 时段预估公式按 Excel 口径修正为"天数 × 日消费人次 × 客单价"（人次缺失时用餐位数 × 上座次数）。
5. 校验：`openspec validate build-catering-analysis-platform --strict` 通过，4/4 产出物完成。
